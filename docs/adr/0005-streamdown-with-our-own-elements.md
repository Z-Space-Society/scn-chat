# Replies render through Streamdown, with every element our own

A reply arrives a few words at a time, so most of it is half-written Markdown: a `**` not yet closed, a link without its address, a fence still open. react-markdown rendered those literally until the closing half arrived, and rendered the whole reply again on each word. Streamdown completes the unfinished Markdown as it streams, renders a reply block by block so finished blocks don't render again, and highlights code incrementally through Shiki, so we render replies and reasoning with it. Its own elements, controls, and link confirmation are styled with shadcn's token names, which our theme doesn't have, and its dark mode follows the system rather than the picker, so every element is one of ours in `parts/markdown.tsx`, styled by `markdown.css`, and its controls and link confirmation are off. It renders raw HTML by default through rehype-raw, which we drop, so HTML in a reply shows as the text it is. Code is colored by Shiki's CSS-variables theme, so its colors are tokens in `theme.css`. Shiki and KaTeX are most of its weight, so each loads the first time a reply needs it. We considered keeping react-markdown and adding Shiki to it, which leaves half-written Markdown flashing and a long reply re-rendering on every word, and Streamdown's own styled components, which would bring a second theme into the app.
