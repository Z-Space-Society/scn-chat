# The web app is extended in code, not through plugins

The people extending this project are programmers working in their own fork, so the web app has no plugin system. A forker changes its code directly, and the project's part is to keep that code easy to change: small components, one table of the components that show each kind of message part, and a guide in `docs/extending.md`. Server plugins stay as they are, since they are npm packages a programmer or admin installs. We considered web halves of plugins, with renderers, slots, and settings panels behind a typed API, and themes users could import. Both would have been a second public contract to version for no audience that needed it, and anything loaded into the browser at runtime could read every chat in the local copy and act as the user. So nothing third-party loads in the browser, and the look comes from a theme of design tokens that forkers and the designer edit.
