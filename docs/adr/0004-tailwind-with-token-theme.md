# Components style themselves with Tailwind, over a theme of tokens

The first plan kept visual decisions out of the components entirely: plain markup, with the look in one global stylesheet a designer would write. The design built that way on `design-reference` grew to about 5,400 lines, most of it descendant selectors reaching into components from afar, over a base layer that gave every button and field a look the components then had to undo. A forker changing one component had to find its rules in that file and could break another page doing it. So components now carry their own styles as Tailwind utilities, and the theme is a file of design tokens that clears Tailwind's built-in palette and scales, so utilities can only name the theme's values. The look is still changed by editing the theme, as ADR 0002 says, and a component's own layout is changed in the component. We considered CSS Modules, which scope styles but leave values free to drift from the tokens and keep a second file per component, and keeping one global sheet split into files, which leaves the reach-in selectors in place. Tailwind also gives forkers a convention most of them already know.
