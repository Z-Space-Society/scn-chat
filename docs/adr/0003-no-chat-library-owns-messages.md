# No AI chat library owns message state in the browser

Messages are records: written to the PDS, synced into the browser's local copy, and branched by parent. The reply stream is only an overlay until the record arrives. Chat client libraries such as the AI SDK's `useChat`, TanStack AI's client, and assistant-ui's runtimes all keep their own message list, which would need adapters in both directions and invites a second source of truth. So the browser's chat logic is our own, on TanStack primitives, reading the local copy. The AI SDK stays on the server, where `@ai-sdk/provider` is already part of the plugin contract. TanStack AI was also rejected there, since it was still a 0.x release candidate and moving to it would break every provider plugin. Part views receive our lexicon types, so no chat library's types reach the code forkers change.
